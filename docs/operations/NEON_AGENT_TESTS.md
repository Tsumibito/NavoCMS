# Neon: выделенная тестовая БД исполнителя

Настроено принимающим для разработки NavoCMS. Staging и production не используются тестами.

| Параметр | Значение |
| --- | --- |
| Project | `NavoCMS-main`, `spring-thunder-53665126` |
| Test branch | `agent-tests`, `br-purple-moon-b1w5xqsh` |
| Compute | `ep-round-darkness-b1wmk3ea` |
| Регион | AWS Frankfurt |
| PostgreSQL | 18; текущий CI использует 17 |
| Мощность | min/max 0.25 CU |
| Автоостановка | `suspend_timeout_seconds: 300` |
| Anchor DB | `navocms_agent_test` |

Ветка создана от default production branch и наследует её роли/схему в `neondb`;
тесты не используют унаследованную базу. Пароль owner изменён только на тестовой ветке.
Для каждого запуска создаётся новая пустая база `navocms_test_<timestamp>_<random>`.
В неё применяются все миграции, provision runtime и синтетический CI bootstrap.
Никакие production fixtures не копируются в рабочую тестовую БД.

## Запуск

Из корня CMS, с Node 22 и установленными зависимостями/Playwright Chromium:

```sh
dotenvx run --quiet -f .env.test -- node scripts/test-neon.mjs
```

Файлы `.env.test` и `.env.keys` уже находятся локально в рабочей папке CMS.
Первый содержит зашифрованные owner URL и test runtime password; второй — локальный ключ
расшифровки. Оба игнорируются Git и имеют права 0600. Не выводить их содержимое, не коммитить
и не переносить ключи в отчёт/чат. Обычный `pnpm check` сам по себе `.env.test` не загружает.

Помощник проверяет точный hostname и anchor DB, запрещает другое окружение, использует direct
TLS connection с проверкой сертификата. Внутри выставляет migration/admin/runtime URLs для
конкретной новой базы. Запускает `pnpm check`, затем 5 isolation SQL и удаляет **только созданную
этим запуском** базу в finally, включая обычное завершение с ошибкой.

Помощник устанавливает `NAVOCMS_NEON_TEST_RUN=true`: test timeout составляет 180 секунд
с учётом сетевых round trips. Обычный запуск и CI сохраняют прежние 10 секунд.
Первый пробный прогон без настройки дал 217 pass и 5 timeout; его временная база удалена.
При 60 секундах осталось 221 pass и один timeout: последовательное создание 45 документов
в pagination fixture. Это test-only лимит для удалённой БД, не SLA приложения.

Neon owner не является PostgreSQL superuser. Для SQL fixtures помощник явно даёт тестовому
`neondb_owner` право `SET ROLE navocms_app` с `INHERIT FALSE`; это локальная для ветки роль.
`navocms_runtime` остаётся `NOBYPASSRLS`. Прикладная роль не получает дополнительных прав.
Для отдельной проверки isolation допустим флаг `--isolation-only`; он не заменяет `pnpm check`.

Advisory lock отклоняет второй одновременный запуск: provision использует общую test runtime
роль. Последовательные прогоны независимы. При аварийном завершении процесса/компьютера
finally может не выполниться; оставшуюся базу с точным именем из начала лога удаляет принимающий
только на этой тестовой ветке. Не выполнять массовую очистку по префиксу.

После завершения соединения закрываются. Neon останавливает compute через 5 минут без запросов;
новый запуск автоматически будит его. Storage сохраняется и оплачивается по условиям проекта:
scale-to-zero прекращает idle compute, но не означает бесплатность всей ветки.
Не добавлять health-polling, cron или постоянно работающий сервер к тестовой БД.

## Проверка при настройке

Проверено 2026-09-05 на исходниках PR head `58d105af3c6f7e94fbd1855b91671423d3f1f86c`
с локальными дополнениями тестового запуска, Node 22.23.1 и Neon PostgreSQL 18:

- `pnpm check`: PASS, 39 файлов / 222 теста, 0 skipped, Playwright 6/6.
- 5 SQL isolation suites: PASS отдельным прогоном после явного предоставления SET ROLE.
  Первый комбинированный запуск прошёл check, но остановился на отсутствии этого права.
- Повторный одновременный запуск отклонён advisory lock до создания базы.
- Созданные базы удалены после успешных и неуспешных запусков; API подтвердил отсутствие
  оставшихся `navocms_test_*` баз. Сохранились только anchor DB и унаследованный `neondb`.
- API подтвердил min/max 0.25 CU и auto-suspend 300 секунд; выключение после финального
  периода простоя не ожидалось вручную и не заявляется как наблюдённый переход состояния.
- `.env.test` / `.env.keys`: encrypted values, локальный ключ, 0600, оба файла Git-ignored.

Логи проверок на этой машине: `/tmp/navocms-neon-final-check.log` и
`/tmp/navocms-neon-isolation-final.log`. Они временные, не являются долговечным CI evidence.
Добавления принимающего оставлены локально для включения исполнителем в корректирующий PR;
GitHub CI исходного head не проверял новые файлы тестового запуска.
